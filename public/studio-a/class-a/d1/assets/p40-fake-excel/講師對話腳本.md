# F 組 D1 跑場景 hands-on · 講師對話腳本

> 對應 slide：HANDS-ON · 跑你的真實場景 + Timer 25 min
>
> F 組 15 人（教育事業部 George 組），主題 = 校園 B2B 銷售 + MDM 裝置管理。
> D1 hands-on 兩軌、學員各挑一份貼近自己工作的 fake Excel 跑（不硬分組）：
> - **Track 1 · 校園客戶標案彙整**（做客戶 / 標案 / 拜訪的人）
> - **Track 2 · 進出貨原廠報備核對**（做進出貨 / 庫存 / 報備的人）
>
> 兩軌都對準 F 組核心痛點：**多個數據表格要交叉確認、資訊分散難整理**。
> MDM 巡檢場景 D1 不跑（待跟 George 對齊細節後排 D2/D3）。

## Track 1 · 校園客戶標案彙整

### 學員拿到的 Excel

`2026-06_校園客戶標案彙整表.xlsx`（在 class-f 根目錄）— **3 個分頁、用「客戶編號」串**：
1. **客戶主檔**（30 筆）：客戶編號 / 學校代號 / 類型 / 區域 / 負責業務 / 合作狀態 / **最後拜訪日**
2. **標案進度**（40 筆）：標案編號 / 客戶編號 / 標案名稱 / 金額 / 階段 / **預計決標日** / 狀態
3. **拜訪記錄**（52 筆）：客戶編號 / 拜訪日 / 業務 / 摘要 / 下一步

> 設計理由：三張表要 join「客戶編號」才看得出全貌 —— 這正是 F 組「多資料表交叉確認、資訊分散」的痛點。學員自己用 VLOOKUP 得開三個檔對半天，Claude 一次跨表整合。

### 學員開場 prompt（投影片已示範）

```
> 我手上有校園客戶標案彙整 Excel（3 個分頁：客戶主檔 /
  標案進度 / 拜訪記錄，用客戶編號串）。以 6/26 為基準，
  幫我列出「本週要優先跟進的客戶」—— 有標案在評選或
  決標前、但最後拜訪超過 14 天的；再標出「標案進度異常」
  —— 預計決標日已過、卻還沒決標的。
```

### Claude 預期 output

跨 3 分頁 join 客戶編號 → 算「最後拜訪距今天數」+ 比對標案階段 → 出兩份清單（待跟進客戶 / 進度異常）。過程會踩到髒資料（見下），Claude 要自己容錯 = 這組「資訊分散、跨表對不上」痛點的 wow 點。

### 預埋「本週待跟進客戶」（應標 5 筆 · 基準日 2026-06-26）

| 客戶 | 學校 | 業務 | 最後拜訪 | 距今 |
|---|---|---|---|---|
| C003 | 校 C（私立大學） | Jim | 2026-06-04 | 22 天 |
| C008 | 校 H（國立高中） | KC | 2026-06-01 | 25 天 |
| C011 | 校 K（國立大學） | Max | 2026-06-01 | 25 天 |
| C016 | 校 P（縣立國中） | Asa | 2026-06-04 | 22 天 |
| C023 | 校 W（國立高中） | Edick | 2026-05-27 | 30 天 |

> 這 5 位都同時滿足「標案在評選 / 決標前」+「最後拜訪 > 14 天」。判斷靠跨「標案」+「拜訪」兩表 —— 只看單表會漏。

### 預埋「標案進度異常」（應標 4 筆 · 預計決標日已過、未決標）

| 標案 | 客戶 | 標案名稱 | 預計決標 | 階段 |
|---|---|---|---|---|
| F021 | C020 | 宿舍網路裝置更新 | 2026-06-21 | 評選 |
| F022 | C022 | 特教輔具平板採購 | 2026-06-13 | 評選 |
| F023 | C025 | 行政 iPad 派發案 | 2026-06-12 | 評選 |
| F024 | C014 | 校園導覽 App 載具 | 2026-06-13 | 評選 |

### 預埋 5 筆「髒資料」（跨表交叉才抓得到，對準「資料分散難整理」痛點）

| 代號 | 位置 | 髒在哪 | Claude 要做什麼 / VLOOKUP 會怎麼錯 |
|---|---|---|---|
| G1 | 標案 F009 | 客戶編號 **C099** 在客戶主檔查無 | 孤兒標案，join 拉不到客戶；Claude 應主動說「F009 對不到客戶」 |
| G2 | 標案 F007 | 金額存成**文字**「1,200,000」（含逗號） | 要轉數字才能加總 / 排序；SUM 會漏這筆 |
| G3 | 客戶 C005 / C025 | 同一所「校 E（國立大學）」**兩個客戶編號**、不同業務登記 | 重複客戶，跨列比對學校代號才發現；分開算會重複計 |
| G4 | 標案 F012 | 預計決標日 **2027 年**（應為 2026、key 錯） | 造成「未來很遠」假象、不會被判成異常；要抓日期離群 |
| G5 | 拜訪記錄 | 客戶編號「**Ｃ003**」全形、對不上主檔「C003」 | 精確 join 會漏這筆拜訪、害 C003 被誤算成更久沒拜訪 |

### 講師巡場 talking points

- **0-3 min**：學員開 Claude Code、把 Excel 拖進 vault（或記路徑 `~/Desktop/2026-06_校園客戶標案彙整表.xlsx`）、念 prompt。常見卡：不知道 Excel 放哪 → 建議放 `inbox/` 或 desktop。
- **3-15 min**：Claude 讀 3 分頁（openpyxl / pandas）、join 客戶編號、算天數。常見卡：Claude 問權限跑 script → 學員按 yes。
- **15-25 min**：跑出兩份清單後 → **先丟髒資料梗**：「有沒有一個標案對不到客戶？有沒有一所學校出現兩次？」讓學員體會 Claude 幫他收拾平常跨表會爆的爛攤子 → 再追問「**這 5 個待跟進的，先打給誰**（金額大 + 階段緊 + 最久沒碰）」「進度異常那幾個，是不是卡在我們這邊」。

### 常見卡點 + 補救

| 卡點 | 補救 |
|---|---|
| Claude 問 Excel 在哪 | 講師示範拖檔到 terminal 或講 `~/Desktop/...xlsx` |
| Claude 跑 script 要權限 | 學員按 yes |
| Claude 只讀一個分頁 | 提醒「三個分頁都要讀、用客戶編號串起來」 |
| Claude 沒抓到髒資料 | 提醒追問「有沒有標案對不到客戶 / 金額是文字 / 學校重複 / 日期怪怪的」 |
| 待跟進算出來不到 5 個 | 提醒「基準日是 6/26、門檻 14 天；再問全形編號那筆有沒有害 C003 算錯」 |
| 學員想存結果 | 講師講「跟 Claude 說『存成 markdown 進 Efforts/Areas/校園客戶/』」 |

## Track 2 · 進出貨原廠報備核對

### 學員拿到的 Excel（規則已內建第 2 分頁）

`2026-06_進出貨原廠報備核對表.xlsx`（在 class-f 根目錄）— **2 個分頁**：
1. **進出貨明細**（61 筆 · 10 欄）：單號 / 日期 / 類型（進貨/出貨/調撥）/ 品項類目 / 型號 / 數量 / 對象 / 教育專案代號 / 原廠報備編號 / 狀態
2. **核對規則**（12 條 + 教育專案授權清單 EDU-001~020）

> ✅ **規則已寫進 Excel 第 2 分頁、不用口頭講或另發 md**（mirror B 組 Kidd v2.1）。學員叫 Claude「連核對規則分頁一起讀」就好。

### 學員開場 prompt

```
> 我手上有 6 月進出貨明細 Excel，第 2 個分頁是「核對規則」。
  請照那些規則逐筆檢查，把數量或報備有疑慮、資料有誤的
  挑出來，每筆說明是違反哪一條規則。
```

### Claude 預期 output

讀兩分頁（明細 + 規則）→ 照 12 條逐筆 check → 出疑慮清單 + 各筆原因（哪一條規則）。

### 預埋「疑慮 / 資料有誤」清單（應挑出 11 筆）

**[A] 報備 / 規則（原廠報備本職）**

| 單號 | 規則 | 疑慮 |
|---|---|---|
| IO2026060004 | 規則 1 | 出貨 55 台 > 50 台上限、原廠報備編號留空 |
| IO2026060010 | 規則 2 | 教育專案代號 EDU-099 不在授權清單 |
| IO2026060015 | 規則 7 | 出貨對象為學校、但教育專案代號留空 |
| IO2026060021 | 規則 3 | 原廠 X 報備寫 40 台，但本月原廠 X 出貨加總 50 台（30+20）→ **少報 10 台** |

**[B] 資料有誤（門市 / 系統 key 錯 → 要特別撈）**

| 單號 | 規則 | 疑慮 |
|---|---|---|
| IO2026060006 | 規則 4 | 日期 2027-06-08 不在當月（2026-06） |
| IO2026060013 | 規則 5 | 數量 -8 為負數 |
| IO2026060019 | 規則 6 | 型號「ｉPad 教育版 A」全形 i、對不上型號主檔 |
| IO2026060025 | 規則 8 | 對象欄留空 |
| IO2026060028 | 規則 5 | 數量 0 |
| IO2026060031 | 規則 8 | 調撥未註明來源門市（只有目的、缺來源） |
| IO2026060034 | 規則 9 | 同一單號 IO2026060034 出現兩列（重複） |

> **最容易漏（需跨列 / 跨欄）**：規則 3（原廠 X 報備 40 vs 出貨加總 50 → 跨兩列相加）+ 規則 9（同單號重複 → 跨列比對單號）。這兩個是追問教學點。

### 講師巡場 talking points

- **0-3 min**：學員把 Excel 給 Claude、叫它**連「核對規則」分頁一起讀**。先確認每人都有開到第 2 分頁。
- **3-15 min**：Claude 照規則 check。最容易漏：① 原廠 X 報備數對不上出貨加總（跨列加總）② 同單號重複（跨列）→ 提醒追問。
- **15-25 min**：跑出清單 → 鼓勵追問「這幾筆該打回哪個門市 / 補哪個報備」「原廠 X 這個月到底該報幾台」「下個月怎麼防門市又 key 錯」。

### 常見卡點 + 補救

| 卡點 | 補救 |
|---|---|
| Claude 只看明細、沒讀規則 | 提醒學員講「連第 2 個分頁『核對規則』一起讀」 |
| Claude 漏掉原廠報備加總對不上 | 提醒追問「同一原廠的出貨加起來、跟報備數字一不一致」 |
| Claude 漏掉同單號重複 | 提醒追問「有沒有同一個單號出現兩次」 |
| Claude 沒抓到日期 / 負數 / 全形型號 | 提醒追問「有沒有日期不在 6 月、數量 ≤ 0、型號打錯的」 |
| 學員想 export | 講師講「跟 Claude 說『把疑慮清單存成 CSV 進 Efforts/Areas/進出貨報備/』」 |

## 共通教學重點

- **Excel 操作不教**：學員已會，focus 在「跟 Claude 對話」這個 leverage。
- **兩軌都埋了「跨表交叉」的坑**：對準 F 組共同痛點 —— Track 1「多資料表交叉確認、資訊分散」（孤兒標案 / 重複客戶 / 全形 join），Track 2「原廠報備跨表拼、門市資料有誤要特別撈」（報備加總對不上 / 同單號重複 / 門市 key 錯）。wow 不只是「Claude 會算」、是「Claude 幫我收拾我每天在收拾的爛攤子」。
- **Claude 是工具不是老師**：學員追問「先打給誰」/「原廠該報幾台」/「打回哪個門市」這種 next-action 才是真實 leverage、不只是「找出問題」。
- **分享環節**：兩軌各抽 1-2 人、各 1 min 講「你問了什麼 / Claude 做了什麼 / 你的下一步是什麼」。
- **MDM 場景 D1 不跑**：待跟 George 對齊「是否 Apple 校園 iPad 部署 + 原廠回報流程」細節後，排進 D2/D3 深案例。開場需求牆 + 三天預告仍列 MDM，讓學員知道後面會做。
